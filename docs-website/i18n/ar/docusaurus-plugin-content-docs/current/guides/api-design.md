# مبادئ التصميم

تشرح هذه الصفحة قرارات التصميم خلف Fanar API. فهم هذه المبادئ يساعدك على بناء تكاملات صحيحة وقابلة للصيانة وجاهزة للتوسع المستقبلي.

## REST و JSON

تتبع جميع واجهات الاستدعاء البرمجية اتفاقيات REST. الموارد عبارة عن أسماء جمع في مسارات URL متوقعة (`/reciters/`، `/recitations/`، `/riwayahs/`). كل جسم استجابة هو JSON مع `Content-Type: application/json`. تحمل أفعال HTTP معناها المعتاد: `GET` للقراءة، `POST` للإنشاء، وهكذا.

## معرّفات موارد ثابتة

لكل مورد حقل `id` صحيح. هذه المعرّفات ثابتة: بمجرد تعيينها، سيشير معرّف القارئ `42` دائماً إلى ذلك القارئ. يمكنك حفظ المعرّفات في قاعدة بياناتك، وتضمينها في URLs، والإشارة إليها عبر الطلبات دون القلق من تغييرها عبر إصدارات الـ API.

## غلاف الاستجابة

تُلفّ واجهات الاستدعاء البرمجية للقوائم المُصفَّحة حمولتها في غلاف متسق:

```json
{
  "count": 150,
  "results": [...]
}
```

`count` هو إجمالي عدد السجلات المطابقة (ليس فقط الصفحة الحالية). `results` يحتوي على صفحة العناصر. واجهات الاستدعاء البرمجية للمورد الواحد تُعيد الكائن مباشرة — بدون غلاف.

راجع [هيكل الاستجابة](/docs/guides/response-structure) للتفاصيل الكاملة.

## الموارد المرتبطة المدمجة

عندما يشير مورد إلى آخر (تلاوة تشير إلى ناشرها وقارئها وروايتها وقراءتها)، يُدمج الـ API كائناً مضغوطاً `{id, name}` مباشرة بدلاً من URL أو مفتاح خارجي صحيح فارغ. يتيح لك هذا عرض عنصر قائمة كامل — الاسم، الأسماء المرتبطة، الأعداد — من طلب واحد.

```json
{
  "id": 7,
  "name": "حفص عن عاصم",
  "publisher": { "id": 3, "name": "إتقان" },
  "reciter": { "id": 12, "name": "مشاري راشد العفاسي" },
  "riwayah": { "id": 1, "name": "حفص" }
}
```

عندما تحتاج السجل الكامل لمورد مرتبط، استدعِ نقطة نهايته الخاصة باستخدام `id` المدمج.

راجع [تضمين الكائنات المرتبطة](/docs/guides/related-resources) لمواصفة النمط الكاملة.

## الحقول المدركة للغة

الحقول التي تحمل نصاً قابلاً للقراءة — `name`، `description`، `bio` — تُعيد المحتوى باللغة المطلوبة عبر ترويسة `Accept-Language`. أرسل `Accept-Language: ar` للعربية، `Accept-Language: en` للإنجليزية. مفتاح JSON دائماً نفسه (`name`، ليس `name_ar` أو `name_en`)؛ القيمة فقط تتغير.

راجع [التوطين](/docs/guides/localization) لاستخدام الترويسة وتغطية الحقول.

## غلاف خطأ موحّد

جميع الاستجابات غير 2xx تشترك في نفس البنية:

```json
{
  "error_name": "not_found",
  "message": "No asset matches the given query.",
  "extra": null
}
```

`error_name` معرّف ثابت يمكن قراءته آلياً — قم بتحويل معالجة الأخطاء بناءً عليه، ليس على `message` أو حالة HTTP. `message` وصف قابل للقراءة البشرية، مُحلَّل عبر `Accept-Language` — آمن للعرض مباشرة للمستخدمين. `extra` يحمل تفاصيل منظمة اختيارية (مثلاً، أخطاء التحقق على مستوى الحقل).

راجع [معالجة الأخطاء](/docs/guides/errors) للكتالوج الكامل للأخطاء.

## التخزين المؤقت

نقاط القوائم (`/recitations/` و`/reciters/` و`/riwayahs/` و`/packages/` و`/recommendations/trending/` و`/recommendations/editorial/` و`/recommendations/similar/{asset_id}/`) ترسل `Cache-Control: public, max-age=60` ومعها `ETag`:

- يجوز للمتصفح أو لشبكة توزيع المحتوى (CDN) إعادة استخدام القائمة حتى 60 ثانية، فقد يتأخر ظهور تعديل الناشر حتى دقيقة.
- بعد ذلك أرسل قيمة `ETag` في ترويسة `If-None-Match`. إن لم يتغير شيء تصلك `304 Not Modified` بجسم فارغ، فتستمر في استخدام نسختك.
- الاستجابات لطلب يحمل مفتاح API تكون `private, max-age=60`: يحتفظ بها عميلك وحده، ولا تحفظها أي ذاكرة مؤقتة مشتركة.

```bash
curl -i {{API_BASE}}/reciters/ -H 'If-None-Match: "3f2a…"'
# HTTP/1.1 304 Not Modified
```

## التطور المتوافق مع الإصدارات السابقة

يتطور الـ API بشكل إضافي. هذه التغييرات قد تصدر في أي وقت ودون إشعار:

- نقاط نهاية جديدة، ومعاملات استعلام اختيارية جديدة، وحقول جديدة في الاستجابات الموجودة
- قيم جديدة لـ `error_name` (تعامل مع القيمة غير المعروفة كخطأ عام)
- قيم جديدة في الحقول ذات القيم المحددة

يجب أن يتجاهل عميلك الحقول غير المعروفة بدلاً من الفشل بسببها. التكامل المبني على `/recitations/` اليوم يستمر في العمل مع إضافة حقول جديدة.

## سياسة الإيقاف التدريجي

المسارات غير مُرقّمة بإصدار: لا يوجد `/v1/` ولا نية لإضافته. أي تغيير مُخلّ (حذف حقل أو نقطة نهاية أو معامل أو إعادة تسميته، أو تغيير نوع أو رمز حالة أو `error_name`) يتبع هذه السياسة بدلاً من ذلك:

1. **الإشعار.** يُعلن عن التغيير في هذا التوثيق قبل **90 يومًا** على الأقل من سريانه.
2. **الترويسات.** خلال هذه الأيام التسعين يستمر السلوك القديم في العمل، وتحمل كل استجابة يمسّها:
   - `Deprecation: @<unix-timestamp>`: وقت إعلان إيقاف السلوك القديم ([RFC 9745](https://www.rfc-editor.org/rfc/rfc9745))
   - `Sunset: <HTTP-date>`: وقت توقفه عن العمل ([RFC 8594](https://www.rfc-editor.org/rfc/rfc8594))
   - `Link: <docs page>; rel="deprecation"`: الصفحة التي تشرح التغيير
3. **أداة itqan أولاً.** يصدر إصدار من أداة سطر الأوامر itqan يتعامل مع السلوك الجديد قبل إزالة القديم.
4. **الإزالة.** بعد تاريخ `Sunset` يزول السلوك القديم.

```http
HTTP/1.1 200 OK
Deprecation: @1798761600
Sunset: Mon, 01 Mar 2027 00:00:00 GMT
Link: <https://docs.example/docs/guides/api-design#deprecation-policy>; rel="deprecation"
```

سياسة CORS تكشف الترويسات الثلاث، فيستطيع كود المتصفح قراءتها. سجّل ترويسة `Deprecation` في عميلك أو نبّه عليها لتعرف بالتغيير قبل تاريخ إيقافه. إصلاحات الأمان، والإصلاحات التي تجعل الواجهة تفعل ما يقوله هذا التوثيق أصلاً، قد تصدر دون مهلة الأيام التسعين.
